CONTROL ID:
AI-ACCESS-001

CONTROL NAME:
User-Level Authorization Before LLM Processing

CONTROL OBJECTIVE:
Ensure that an AI system receives only customer information
the authenticated user is authorized to access.

RISK ADDRESSED:
Unauthorized cross-customer disclosure caused by excessive
LLM context, prompt injection, role manipulation, or failure
to enforce authorization before model processing.

CONTROL IMPLEMENTATION:
Authorization is enforced by the application before the LLM
request is constructed.

The authenticated user is identified as "alice".

The application retrieves only Alice's authorized customer
record and sends that record to the LLM.

Other customer records, including Kwame Asante's record,
remain outside the model context.

The LLM therefore cannot retrieve another customer's data
merely because the user requests it or attempts to override
the application's access-control rules.

RESIDUAL RISK:
Residual risk remains because the test environment uses a
simplified authentication and authorization model.

Production implementation would require validated identity,
session management, server-side authorization, role and
attribute enforcement where appropriate, audit logging,
multi-user testing, authorization-failure handling, and
protection against indirect data retrieval paths.

ASSESSOR CONCLUSION:
AI-ACCESS-001 operated effectively across the tested
scenarios.

The primary security mechanism is application-layer
authorization before LLM processing rather than reliance
on the model to determine which customer records a user
may access.

This reduces the impact of prompt injection and role
manipulation because unauthorized customer records are
excluded from the model context.

The test results support control effectiveness for the
defined scenarios but do not constitute production
approval.
